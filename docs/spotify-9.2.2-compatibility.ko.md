# Spotify 9.2.2 호환성 점검

대상은 사용자가 제공한 복호화된 원본 Spotify **9.2.2 (920202587)**, arm64 UUID `BEDF0071-845D-39BB-B2D0-96F9A8095E66`입니다. 실행 파일의 `cryptid=0`, 최소 iOS 16.1을 확인했습니다. 기존 9.1.90 원본과 코드는 보존했습니다.

## 반영한 대응

- 광고 서비스의 구형/신형 클래스 이름 모두에 기존 광고 차단 설정을 연결했습니다. 9.2.2의 새 서비스에서 `load`가 실제로 존재하는지 원본 메타데이터로 확인했습니다.
- Native 플레이어의 크레딧 숨김이 새 `CreatorElements_Credits` 모듈도 식별하도록 했습니다. 이전 모듈명도 유지합니다.
- Redesigned 아티스트 팔로우에서 없어진 Curation 구독 메서드는 실제 존재할 때만 후킹합니다. 기존 collection/state-provider 연결은 유지합니다.
- Redesigned 보관함 헤더는 기존 직접 자식을 먼저 찾고, 없으면 UIKit UIStackView 안에서도 찾습니다. 임의의 다른 컨테이너까지 탐색하지 않습니다.

## 검증 범위

- 원본 9.1.90/9.2.2의 Objective-C 클래스·메서드 메타데이터를 비교하고, 현재 hook 대상과 selector 참조를 점검했습니다. 플레이어 상태·트랙·링크 디스패처·내비게이션 reason의 사용 중인 API 유지 여부를 확인했습니다. 이는 Swift 내부 상태와 모든 화면 동작의 완전한 보장이 아닙니다.
- 9.2.2 원본에 수정 트윅을 넣은 별도 Simulator 앱에서 Native 및 Redesigned 모드의 로그인 화면까지 실행, Mod Settings, 플레이어 설정, 무손실 설정 페이지 이동을 확인했습니다. 원본 작업 디렉터리의 플래그 표는 변경하지 않았습니다.
- 보관함 하네스는 직접 배치와 UIStackView 중첩 배치에서 제목 표시·원래 제목 숨김을 검증합니다. SDK의 scene lifecycle 요구도 공통 하네스 scene에 연결했습니다.
- 수정 Logos 파일의 iOS arm64 strict 컴파일, 레이어·패치 공백 검사를 실행했습니다.

사용자 요청에 따라 로그인하지 않았습니다. **로그인 이후 실제 재생·대기열·FLAC 정렬/전환·애드온·유선 출력·실기기 동작은 이 버전에서 확인하지 않았습니다.** 따라서 9.2.2는 `SGSpotifyLikelyWorksVersions`에만 등록하며, About에 ‘작동 가능’으로 표시합니다. 기존 지원 버전은 그대로 유지합니다. 9.2.0은 새 원본으로 검사하지 않았으므로 별도로 등록하지 않습니다.

## 빌드

로컬에 보존한 원본을 명시합니다.

```sh
make release IPA=ipa/Spotify-9.2.2.ipa
```

GitHub Actions에서는 9.2.2 **원본**의 직접 다운로드 주소를 입력해야 합니다. 파이프라인은 입력 IPA의 버전에서 플래그 표를 다시 추출합니다. 이 작업에서 배포용 IPA, 서명, 설치, 커밋 또는 푸시는 하지 않았습니다.
