# 재생바 아래 음질 배지

기본 화면과 Redesigned 화면의 재생바 아래, 양쪽 시간 표시 사이에 테두리 없는 글자와 작은 아이콘을 표시합니다. 재생바와 간격을 두고 36pt 높이의 터치 영역을 사용합니다.
배지를 누르면 음질, 원본 샘플레이트, 출력 샘플레이트, 리샘플링, 소스를 보여주는 팝오버가 열립니다.
팝오버의 상세 재생 정보 버튼은 기존 Playback details 화면으로 이동합니다.

최근 외부 PCM 교체가 확인된 경우에만 파일 디코더 정보로 무손실을 표시합니다.
BitChord 기준처럼 실제 16비트 초과 또는 실제 48 kHz 초과인 파일은 고해상도 무손실로 표시합니다. 따라서 24-bit/48 kHz도 고해상도 무손실입니다.
공급자의 96 kHz 주장만 있고 실제 파일이 48 kHz라면 실제 48 kHz 값으로 표시합니다.
Spotify 자체 스트림의 음질이 확인되지 않은 경우에는 배지에는 기본을 표시하고,
팝오버에서 확인하지 못한 포맷 값은 확인 불가로 남깁니다. 실제 탐색·정렬 작업이 진행 중이면 음원 찾는 중을 표시합니다. 일시정지나 재정렬로 최근 재생 확인이
없어진 경우에도 무손실임을 추정하지 않습니다.

배지의 음질은 원본 파일 형식입니다. 파일·앱·장치 사이의 레이트 변환은 리샘플링 항목에
따로 표시합니다. 무손실 배지나 레이트 일치 자체가 전체 출력의 bit-perfect를 증명하지 않습니다.

Native와 Redesigned는 각각 자기 레이어의 훅과 배지를 사용합니다. 표시 데이터와 독립적인
팝오버만 Shared에 둡니다. 기존 DurationElementUnit 클래스와 시간 표시 식별자는
제공받은 Spotify 9.1.90 바이너리 및 기존 재생 화면 코드의 기록에서 확인했습니다.
Spotify의 재생바 크기나 스택을 바꾸지 않으며, 배치를 확인할 수 없는 화면에는 배지를 추가하지 않습니다.
재생바를 그리는 매 프레임 대신 화면이 표시되는 동안 1초 간격으로 갱신합니다.

검증: 변경한 Objective-C와 Logos를 로컬 iOS SDK로 arm64 컴파일했고 레이어 규칙과 문법을
확인했습니다. 시뮬레이터 하네스에는 두 화면 모드 각각 배지 배치·탭·팝오버·상세 화면 이동과
공급자 메타데이터만으로 무손실을 표시하지 않는 검사를 추가했습니다.
로컬에는 Xcode가 없어 이 실행 검사는 GitHub Actions에서 확인해야 합니다.

## 탭과 글자 강조

음질 컨트롤은 재생바 유닛의 히트 테스트와 탐색 제스처 영역 밖인 플레이어 목록에 놓입니다.
원래 시간 표시나 재생바 자체의 레이아웃은 바꾸지 않습니다. 일반 한 번 탭으로 팝오버를 열며
길게 누르기를 요구하지 않습니다. 무손실이 확인된 경우에만 3초 주기로 밝은 띠가 글자를 훑습니다.
줄어든 동작, 저전력 모드, 비활성 앱 상태에서는 강조 애니메이션을 멈춥니다.
이 효과는 제공된 BitChord PlayerControls.swift의 강조 방식을 참고했습니다.

## 전체 화면 아트워크

기본 화면: Player → Artwork background 안에 Static cover fallback과 Fill artwork to bottom이 있습니다.
Redesigned: Player의 Artwork layout 항목에 같은 두 옵션이 있습니다. 두 옵션은 기본적으로 꺼져 있습니다.
정지 커버 대체는 움직이는 아트워크가 없을 때 앨범 이미지를 화면 전체에 사용합니다.
화면 아래까지 채우기는 움직이는 아트워크도 비율을 유지하며 확대·크롭해 컨트롤 뒤까지 채웁니다.
그림 아래쪽을 단색으로 바꾸는 대신 이미지를 유지하면서 읽기 쉬운 어두운 그라데이션을 둡니다.
앨범 이미지 자체가 없으면 기존 기본 배경을 유지합니다.
Native의 움직이는 배경은 기존 Shared 애니메이션 소스와 캐시를 사용하며 첫 프레임을 표시하지
못하면 원래 화면 또는 정지 커버로 돌아갑니다. 배경 비디오는 무음이고 재생 화면을 벗어나면 멈춥니다.
WireGuard나 오디오 출력 설정은 이 변경에 포함하지 않습니다.
