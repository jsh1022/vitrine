# 재설계 플레이어: 재생·음질 정보의 범위

이 문서는 재설계 플레이어의 재생 기록, 애드온 전환 방식, 재생 정보와 대기 목록이 무엇을 보여 주고 보장하는지 정리합니다. Spotify에서 확인할 수 없는 값은 추정해 표시하지 않습니다.

## 1. 곡의 전체 재생 횟수

Spotify 데스크톱처럼 모든 청취자를 합산한 곡별 평생 재생 횟수는 구현되어 있지 않습니다. 현재 Spotify 앱 바이너리와 프로젝트의 검증된 인터페이스에서 그 값을 주는 API를 확인하지 못했습니다. 인기 곡 순위나 인기도를 전체 재생 횟수로 바꾸어 표시하지 않습니다.

Vitrine의 Listening Stats는 별도 기능입니다. 이 기기에서 관찰한 재생을 기록하거나 Spotify 계정 내보내기 파일을 가져와 기간별 통계를 계산합니다. 개인 기록이며 Spotify 전체의 곡별 누적 값이 아닙니다.

## 2. Spotify 스트림의 코덱과 비트레이트

Spotify 기본 스트림의 실제 코덱, 원본 샘플레이트, 비트 깊이, 압축 비트레이트는 확인할 수 없습니다. Spotify의 음질 설정 단계는 선택값일 뿐 실제 협상된 비트레이트가 아니므로 kbps나 코덱으로 환산하지 않습니다.

상세 재생 정보는 측정 위치를 나눠 표시합니다. 외부 FLAC/ALAC 파일에서는 파일 디코더가 읽은 코덱·레이트·비트 깊이와 파일 평균 비트레이트를 보여 줍니다. RemoteIO에 도달한 PCM 형식과 클라이언트 레이트, iOS 오디오 세션/출력 기기의 레이트는 별도 측정값입니다. Spotify 출력 PCM을 알아도 압축 원본의 형식이나 비트레이트를 알 수 있는 것은 아닙니다.

## 3. 애드온 재생 방식과 다음 곡 준비

재설계 플레이어의 애드온 재생 방식은 세 가지입니다.

- **빠른 재생**: 애드온을 조회하거나 기다리지 않고 Spotify 기본 스트림을 바로 재생합니다.
- **연속 재생 우선**: 현재 곡은 Spotify로 바로 재생하면서 Spotify가 제공한 대기 순서에서 다음 최대 4곡의 준비를 시도합니다. 비과금 Wi-Fi에서는 바로 다음 곡 전체와 나머지 최대 3곡의 앞부분을 곡당 최대 2 MiB까지 받으려 합니다. 모바일 데이터로 바로 다음 곡 전체를 준비하려면 일반 셀룰러 다운로드 허용과 “모바일 데이터로 다음 곡 전체 준비”를 모두 켜야 합니다. 현재 곡은 별도 자동 전환 스위치가 켜져 있을 때만 안전한 정렬 뒤 외부 파일로 전환합니다.
- **애드온 우선 재생**: 재생 중인 곡에서 애드온 준비를 기다립니다. 대기는 5~30초로 제한됩니다. 준비에 성공해도 재개 후 Spotify가 약 4초간 소리를 내어야 출력과 파일의 상관 분석을 할 수 있고, 나머지 기존 handoff 조건도 통과해야 바뀝니다. 준비 실패나 시간 초과 때는 Spotify 스트림으로 돌아갑니다.

대기 중에는 Spotify를 일시정지하고, 준비가 끝나면 같은 곡을 계속 재생 중이고 사용자가 재생 명령을 바꾸지 않은 경우에만 다시 시작합니다. 대기 시간이 끝나면 Spotify 스트림으로 재개합니다. 첫 소리부터 애드온으로 재생된다는 보장은 없습니다. 소스별 API 요청은 분당 5회 예산과 429 재시도 대기를 공유합니다. 예산이나 제한 시간 때문에 일부 곡만 준비될 수 있고, 다음 제한된 재시도 전까지 준비가 늦어질 수 있습니다.

전송은 HTTPS와 응답 크기·시간 제한을 사용합니다. 부분 파일 이어받기는 강한 ETag가 있을 때 `Range`와 `If-Range`로 검증합니다. 곡이나 설정이 바뀌면 진행 중 요청을 취소하고 오래된 결과를 버립니다. 소스별 분당 요청 예산에 걸린 준비 계획은 큐가 그대로일 때 60초 뒤 제한된 재시도를 예약합니다. 전체 곡 목록을 내려받거나 오프라인 라이브러리를 만드는 기능은 아닙니다.

## 4. 유선 출력과 비트 일치

유선 원본 출력은 지원되는 로컬 무손실 파일에서 iOS 출력 레이트를 원본에 맞추도록 요청하고, 실제 RemoteIO 클라이언트와 출력 기기 레이트를 확인합니다. 라우트나 설정이 바뀌면 Vitrine이 변경한 선호 레이트를 복구합니다. 해당 유선 설정에서는 소스 레벨 보존을 위해 엔진 게인을 1로 둡니다.

이 동작은 전체 신호 경로의 bit-perfect 재생을 보증하지 않습니다. Spotify/iOS가 소유한 오디오 세션, 기기 제한, 속도·피치, DSP, 리샘플링 및 출력 하드웨어의 처리를 모두 우회한다고 주장하지 않습니다. 상세 정보는 측정값과 확인 불가 항목을 따로 표시합니다. 무손실 표시는 BitChord Android 앱의 벡터 경로를 그대로 가져와 템플릿 이미지로 렌더링합니다.

## 5. 이전 곡·현재 곡·다음 곡

이전 재생 화면은 Spotify의 현재 상태가 제공하는 `reverse`, 현재 트랙, `future`를 세 구역으로 표시합니다. 반복된 트랙 항목도 그대로 남깁니다. 이전/다음 항목을 누르면 Spotify의 대상 곡 건너뛰기 명령에 그 상태가 가진 트랙 객체를 전달합니다. 셔플·반복 설정을 바꾸거나 대기열/재생 컨텍스트를 다시 만들지 않습니다. 화면의 “Spotify 대기열” 버튼은 Spotify의 기본 대기열을 엽니다.

Spotify 상태가 바뀌어 화면에 보인 목록이 오래된 경우 선택을 거부합니다. 대상 곡 명령을 현재 Spotify에서 사용할 수 없는 경우에도 대기열을 재구성하지 않고 Spotify 기본 대기열을 안내합니다. 이 기능은 Redesigned UI의 플레이어 설정에서 켭니다.

## 검증 현황

다음 검사는 실행해 통과했습니다: WireGuard 포함/제외 오디오 소스 컴파일, Native/Redesigned 오디오 프레젠테이션과 PCM 측정 분리 검사, Player History 시뮬레이터 14개 검사, 애드온 전송 delegate 및 재생 대기·취소·정책 검사, lossless handoff 실패 횟수 0회 검사, 미니플레이어 전환 60개 시나리오, 한 줄 가사와 정지 커버 및 움직이는 아트워크 26개 검사.

이 검사들은 실제 Spotify 앱과 장치를 대체하지 않습니다. 최종 IPA 패키징 결과는 배포 보고에 따릅니다. 특히 실제 애드온 서버, 모바일 데이터, WireGuard와 실제 출력 기기 조합은 시뮬레이터 검사만으로 검증되지 않습니다.
